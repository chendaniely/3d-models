## Decided without Dan

Under "oneshot the rest of the repo" (and the mode, fully vibed), these are the agent's calls, made
2026-11-05 while writing the spec. Each says why, and what it costs if it's wrong.

| # | Decision | Why | If it's wrong |
|---|---|---|---|
| D1 | Phase 1 is the repo itself (CI, the gallery site, `make models`, a dowel fit-test coupon); Phase 2 is the wall sconce | answer 2 named the sconce as Phase 1 before the scope widened to every print; the sconce needs the coupon and the pipeline anyway | the sconce starts one phase later |
| D2 | Designs are saved as plain-text JSON `.sc`; the STL, PNG, measurements and a build record are committed beside them; freshness is judged by the design's SHA-256 | SolidCraft can't run in CI; a test export showed the same design gives a byte-different STL each time; text designs can be leak-scanned and diffed | a design saved from the app as a zip still builds; only diffs and the leak scan lose out (Later, S17) |
| D3 | Agents build models headless with `solidcraft-cli` from a command script, then save the design | the SolidCraft MCP server isn't set up for this repo; the CLI builds, measures and pictures a design without the app | Dan doesn't watch the model being built; he can open the `.sc` in the app afterwards |
| D4 | The viewer is three.js 0.187.0 from jsDelivr through an import map, no build step | the smallest thing that renders an STL in a browser; pinned so it can't change under the site | a jsDelivr outage blanks the viewer; the picture and downloads still work |
| D5 | The sconce's dowel is 1 inch (25.4 mm) | 4.5 mm long-term sag at 20 inches with a 1 kg lamp, a 21× margin, and the same size as The Rail | a heavier, pricier dowel than 3/4 inch |
| D6 | A straight cantilever | the cleanest line, and fine with a 1-inch dowel; the knee brace waits in Later (S15) | a failed load test brings the knee brace back |
| D7 | A stand-alone wall block, not a Rail attachment | Dan has no Rail on that wall as far as the kickoff showed; the 1-inch dowel keeps the parts compatible | a Rail adapter later |
| D8 | A PLA look test before any load-bearing print | Dan's doubt is whether it looks good; a look test settles that for a few grams of filament | one extra print |
| D9 | PETG, matte, for load-bearing parts, printed on its side | PLA creeps and softens near a warm bulb; on its side, the layers run along the socket | ASA if the bulb base runs hotter than PETG takes |
| D10 | A uv project (`pyproject.toml`, `uv.lock`) with pytest, ruff, PyYAML and Pillow | Dan's rule: everything Python runs under uv | none worth naming |
| D11 | `make photos` fails on GPS data in a JPEG or PNG under `models/`, and on any HEIC (convert it first); `scripts/photos.py strip` removes the metadata | answer 5's rule: photos have their GPS location stripped before they're committed | a format the check doesn't read (it refuses the HEIC it can't read) |
| D12 | Phase 1's first model is a 1-inch dowel fit-test coupon: one bar, four holes at +0.2, +0.4, +0.6 and +0.8 mm | dowels vary by about ±0.5 mm and printers by more; the sconce's socket takes its clearance from the hole that fits | a second coupon at other clearances |

  server's arguments in the MCP client configuration. The alternatives are saving to its recovery
  folder and copying the file in, or building headless with `solidcraft-cli run`.
